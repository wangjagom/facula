1무엇을 만드나요

매장 직원이 상품 번호를 넣고 실행하면, 그 상품의 이름·가격·통화를 보여 주는 조회 프로그램이에요.

위 흐름 그림처럼 값이 입력 화면 → 프로그램 → DB 테이블 → gs_edu → 출력 화면으로 이동해요. 이 중 DB에서 꺼내 gs_edu에 담는 부분이 SELECT ... WHERE 한 문장이에요.

2직원이 상품 번호를 넣어요

PARAMETERS pa_objid가 입력 화면(Selection Screen 1000)에 칸을 만들어요. 직원이 A002를 넣고 실행(F8)을 누르면 값이 pa_objid에 들어가요.

그다음 START-OF-SELECTION 아래 코드가 위에서부터 실행돼요. gs_edu의 세 칸은 아직 비어 있어요.

3SELECT 문을 우리말로 읽어 보면

네 줄을 한 문장으로 읽으면 이래요.

ZTC0503 테이블에서 OBJID가 입력값(A002)인 줄 하나를 찾아, 그 줄의 OBJTX·PRICE·WAERS를 gs_edu의 세 칸에 차례로 넣어 줘.

색깔이 코드의 줄과 같아요. FROM은 어디서, WHERE는 어떤 줄, SELECT는 어떤 칸, INTO는 어디에 담을지예요.

4쓰는 순서와 실행 순서가 달라요

코드는 SELECT → FROM → INTO → WHERE 순서로 쓰지만, DB는 이렇게 처리해요.

  1. FROM: 어느 테이블인지 정해요
  2. WHERE: 조건에 맞는 줄만 남겨요
  3. SELECT: 남은 줄에서 필요한 칸만 골라요
  4. INTO: 고른 값을 변수에 담아요

코드 오른쪽 동그라미 숫자가 실행 순서예요. 이제 이 순서대로 따라가 볼게요.

5① FROM ztc0503: 테이블을 정해요

프로그램이 DB에 "ZTC0503 테이블을 볼게요"라고 요청해요. 지금은 테이블 전체가 후보예요.

맨 앞 MANDT는 적지 않아도 로그인한 Client(100)의 줄만 봐요.

6② WHERE objid = pa_objid: 줄을 골라요

pa_objid 자리에 입력값 'A002'가 들어가요. 그래서 OBJID가 A002인 줄만 남고 나머지는 빠져요.

OBJID는 키라서 같은 값이 두 줄일 수 없어요. 키로 찾았으니 결과는 많아야 1건이고, 그래서 SINGLE과 잘 맞아요.

7③ SELECT objtx price waers: 칸을 골라요

남은 한 줄에서 OBJTX, PRICE, WAERS 세 칸만 꺼내요. OBJID, STOCK 같은 다른 칸은 가져오지 않아요.

이렇게 해서 "모니터, 320000, KRW" 결과 1줄이 만들어져요. 금액(PRICE)은 통화(WAERS)와 함께 있어야 뜻이 정해져서 같이 가져와요.

8④ INTO: gs_edu에 담아요

결과 1줄의 값이 프로그램으로 돌아와서, 괄호 안에 적은 순서대로 들어가요.

  • 1번째 objtx → gs_edu-objtx
  • 2번째 price → gs_edu-price
  • 3번째 waers → gs_edu-waers

이름이 아니라 순서로 짝을 지어요. 괄호 안 순서를 바꾸면 엉뚱한 칸에 들어가요.

9찾았으면 화면에 보여 줘요

찾았으니 sy-subrc가 0이에요. IF sy-subrc = 0.을 통과해서 WRITE가 gs_edu의 값을 출력 화면에 찍어요.

이렇게 직원은 "모니터 320,000 KRW"를 보게 돼요. 흐름 그림의 마지막 칸까지 왔어요.

10없는 번호를 넣으면?

직원이 A009를 넣었다고 해 볼게요. WHERE에서 남는 줄이 없어서 결과가 0건이고, sy-subrc가 4가 돼요.

gs_edu는 바뀌지 않고, IF에서 막혀 아무것도 출력되지 않아요. sy-subrc 확인을 빼먹으면, 앞에서 남아 있던 값이 잘못 출력될 수 있어요.

11요즘 문법으로 쓰면

하는 일과 실행 순서는 똑같고, 모양만 달라요.

  • 필드 사이에 쉼표
  • 변수 앞에 @
  • INTO를 맨 끝에. 순서가 같으면 INTO @gs_edu처럼 Structure 하나로 받을 수 있어요

한 문장 안에서 두 모양을 섞으면 문법 오류가 나요. 회사 코드가 어느 쪽인지 보고 맞춰 쓰면 돼요.
